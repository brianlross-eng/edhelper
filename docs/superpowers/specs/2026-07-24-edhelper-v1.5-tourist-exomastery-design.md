# ED Helper v1.5 — Tourist Planner + Expressway to Exomastery

**Date:** 2026-07-24
**Status:** Approved under the standing overnight authorization (recommended-default
choices; user asleep). Probe-verified before design — see the "Tourist routes" and
"Exomastery routes" sections of `docs/superpowers/notes/2026-07-24-spansh-api-findings.md`
and fixtures `tourist-route-*.json` / `exomastery-route-*.json`.
**Builds on:** v1.4 (Fleet Carrier Router, merged)

## Purpose

Two more Spansh tools in one phase:
- **Tourist Planner**: visit a list of systems in optimized order (Spansh solves
  the ordering), with FSDJump waypoint auto-advance + clipboard copy.
- **Expressway to Exomastery**: exobiology route (high-value biological landmarks
  on landable bodies) — joins the EXPLORATION tool as a fifth mode rather than a
  sixth pill, because its form and results are exploration-shaped.

## Probe findings that shape the design

- Tourist: `POST /api/tourist/route`, params `source` (NAME, not id64), repeated
  **singular** `destination` keys, `final_destination` (always sent, may be `""`),
  `range`, `loop` ('1' site default). Result `result.system_jumps[]` with
  `{system, jumps, distance, id64, x,y,z}`; source is entry 0 with `jumps: 0`
  (neutron pattern); with loop=1 the source repeats as the final entry; **no
  aggregate totals**; id64 typing is MIXED (numbers and strings in one array —
  ignore id64 entirely); inline `{status:'error'}` submit branch exists.
- Exomastery: own endpoint `POST /api/exobiology/route` (internal name
  "exobiology"), NOT /riches/route. Params: `from`, optional `to`, `range`,
  `radius` (25), `max_results` (100), `max_distance` (50000), `min_value`
  (**10,000,000** site default — filters on `landmark_value`, not scan value),
  `avoid_thargoids` ('1' site default), `loop` ('1' site default). Result:
  riches-style waypoints with `bodies[]`; each body adds `landmark_value` and
  `landmarks[] {type, subtype, count, value}`; **`landmark_value` ≠
  sum(landmarks[].value)** — display both, derive neither. Source waypoint has
  `jumps: 1` (riches quirk — normalize to 0). Read string `id64`, never `id`.

## Decisions (autonomous, recommended defaults)

| Topic | Decision |
|---|---|
| Tourist UI | Fifth tool pill "TOURIST". Destinations = one textarea, one system name per line (blank lines ignored). `final_destination` sent as `''` (pin-last-stop is a deferred follow-up). Loop checkbox default ON (site default). Range ship-prefilled. |
| Tourist tracking | New `WaypointTracker<TouristWaypoint, TouristRoute>` (default FSDJump events). Joins the travel-route exclusion group → **four-way** exclusion (neutron/exploration/carrier/tourist each clear the other three on start; trade coexists). |
| Exomastery placement | Fifth mode chip "Exobiology" in the existing EXPLORATION tool. Selecting it switches min-value default to 10,000,000, calls `plotExomastery`, and renders landmark data. Reuses the exploration tracker, IPC, and exclusion as-is. |
| Exomastery types | `ExplorationBody` gains optional `landmarkValue?: number` and `landmarks?: ExplorationLandmark[] {type, subtype, count, value}`; `ExplorationRoute` gains optional `totalLandmarkValue?: number`. Existing modes simply omit them. |
| Notices | All travel-route exclusivity notices become one uniform sentence: "Starting replaces any other active travel route." (three-tool lists were getting unwieldy). |
| Avoid Thargoids | Exomastery passes the existing EXPLORATION checkbox; site default ON for exobiology — when the Exobiology mode is selected, default the checkbox to checked. Tourist has no such param. |

## Architecture (same seams as v1.2–v1.4)

1. **SpanshClient.plotTourist(req)**:
   ```ts
   interface PlotTouristRequest { source: string; destinations: string[]; range: number; loop: boolean; }
   interface TouristWaypoint { system: string; jumps: number; distance: number; }
   interface TouristRoute { waypoints: TouristWaypoint[]; totalJumps: number; totalDistanceLy: number; }
   ```
   Form: `source`, repeated `destination`, `final_destination: ''`, `range`,
   `loop`. Handle the inline submit-error branch. Poll guard: completed OR
   non-empty `result.system_jumps`. Map: waypoint jumps/distance verbatim
   (source row already jumps 0); totals summed client-side.
2. **SpanshClient.plotExomastery(req)**:
   ```ts
   interface PlotExomasteryRequest {
     from: string; to?: string; jumpRange: number; radius: number;
     maxResults: number; maxDistance: number; minValue: number;
     loop: boolean; avoidThargoids: boolean;
   }
   // returns ExplorationRoute (extended body fields present)
   ```
   Form: `from`, optional `to`, `range`, `radius`, `max_results`,
   `max_distance`, `min_value`, `avoid_thargoids`, `loop`. Source-row jumps
   normalized to 0; totals summed client-side incl. `totalLandmarkValue`.
3. **Host RPC**: `plotTourist`, `plotExomastery`. **Main**: tourist tracker
   instance (clipboard copy, default FSDJump); four-way exclusion; IPC
   `tourist:plot/start/clear/get/anchor` + `tourist:updated`.
4. **Renderer**: `TouristPlanner` view (source/range prefilled, destinations
   textarea, loop checkbox, plan list with per-leg distance/jumps, START/CLEAR/
   Copy anchors, uniform notice); EXPLORATION gains the "Exobiology" mode chip
   (min-value + avoid-thargoids defaults switch on selection; body rows show
   `landmark_value` cr and a landmarks sublist "Tussock Stigmasis ×155 ·
   19,010,800 cr"); cockpit tourist card; notice text unified across all four
   travel views.
