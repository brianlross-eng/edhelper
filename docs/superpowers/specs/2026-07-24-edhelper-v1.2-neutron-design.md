## Purpose

Add the second Spansh tool: long-range neutron-supercharged route plotting, with
the companion-app advantage the website can't offer — journal-driven waypoint
auto-advance and automatic clipboard copy of the next system, so in-game the
player just pastes into the galaxy map and jumps.

## Architecture

Same probe-first pattern as v1.1. All new logic follows existing seams:

1. **API verification task first**: probe `POST https://spansh.co.uk/api/route`
   (expected params: `efficiency`, `range`, `from`, `to`) and its
   `GET /api/results/<job>` shape (expected: `system_jumps` list with `system`,
   `distance_jumped`, `distance_left`, `jumps`, `neutron_star`); record fixtures to
   `packages/app/fixtures/spansh/` and a findings addendum; amend the plan if
   reality differs.
2. **SpanshClient.plotNeutron(req)** — same job-submit/poll/backoff machinery,
   mapping to:
   ```ts
   interface NeutronWaypoint { system: string; distanceJumped: number; distanceLeft: number; jumps: number; neutronStar: boolean; }
   interface NeutronRoute { waypoints: NeutronWaypoint[]; totalJumps: number; totalDistanceLy: number; }
   interface PlotNeutronRequest { from: string; to: string; jumpRange: number; efficiency: number; }
   ```
3. **Engine-host**: new RPC `plotNeutron(req)`. (No EDDN interaction; neutron
   plotting is read-only.)
4. **NeutronTracker** (Electron main, sibling of RouteTracker): holds
   `NeutronRoute` + `currentWaypoint` index; consumes parsed `FSDJump` events
   (already emitted by the watcher). When the jumped-to system equals the NEXT
   waypoint (case-insensitive), advance and copy the following waypoint's system
   name via Electron `clipboard.writeText` (clipboard fn injected for tests).
   `start()` copies waypoint 1. `anchor(index)` jumps the tracker to a waypoint
   (used by manual copy buttons) and copies that system. Emits 'updated'
   (`ActiveNeutronRoute | null`).
5. **IPC/preload**: `neutron:plot`, `neutron:start`, `neutron:clear`,
   `neutron:get`, `neutron:anchor`; push channel `neutron:updated`. Types in
   `ipc-types.ts` (`ActiveNeutronRoute { route, currentWaypoint, waypointStatus[], copiedSystem }`).
6. **Renderer**:
   - Tool switcher: two pills (TRADE PLANNER / NEUTRON PLOTTER), local state in App.
   - `NeutronPlotter` view: from (ship-prefilled, editable), to (free text +
     quick-pick chips: Colonia, Sagittarius A*), jump range (prefilled from
     `ship.maxJumpRange`, editable), efficiency (default 60). PLOT → waypoint
     list (neutron badge, jumps count, distances) → START ROUTE → checklist with
     done/next/pending markers, per-waypoint copy buttons, CLEAR.
   - `CockpitPanel`: compact card for an active neutron route
     ("Waypoint N of M → <system> · copied to clipboard") alongside the trade card.

## Error handling

Same conventions: Spansh failure → error text in the tool + footer reachability;
unknown systems → Spansh's own error message surfaced; tracker never throws on
unmatched jumps (no-op). Clipboard failures are logged, never fatal.

## Testing

- SpanshClient neutron tests against recorded fixtures (mapping, error paths).
- NeutronTracker unit tests: start-copies-first, advance-on-matching-jump +
  copy-next, non-matching jump no-op, anchor/re-copy, completion, clear,
  injected-clipboard assertions.
- Host RPC integration test via the existing mock-server harness.
- Renderer component tests: switcher renders both tools; NeutronPlotter prefill;
  waypoint checklist states; cockpit neutron card.
- Live smoke: plot a real neutron route (e.g. current system → Colonia),
  verify waypoint 1 lands on the clipboard on START, record results.

## Out of scope for v1.2

- Galaxy Plotter's extra constraints (refuel stops, supercharge toggles) — later tool.
- Auto-plotting the in-game route (impossible; the game has no API — clipboard is the ceiling).
- Persistence of active routes across restarts (existing deferral).
