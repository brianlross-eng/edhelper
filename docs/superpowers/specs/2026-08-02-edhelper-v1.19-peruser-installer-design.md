# ED Helper v1.19 — Per-user-only installer

**Date:** 2026-08-02
**Status:** Approved (Brian: "I'm showing 2 ED Helper's on my desktop… One for
this user only, one for system wide. A mistake during update installation.")

## Root cause

`nsis.oneClick: false` builds the ASSISTED installer, and with elevation
allowed (the default) it presents an "install for all users" option. Choosing
it installs to `C:\Program Files\ED Helper` and registers under HKLM — it does
NOT upgrade an existing per-user copy, so the machine ends up with two parallel
installs. Observed on the author's PC:

- HKCU `ED Helper 1.0.7` → `%LOCALAPPDATA%\Programs\ED Helper` (desktop
  shortcut target)
- HKLM `ED Helper 1.0.8` → `C:\Program Files\ED Helper`

Same product GUID, two entries, two copies. Settings were never at risk —
both read `%APPDATA%\ED Helper`.

## Decision

Add `allowElevation: false` alongside the existing `perMachine: false`, so the
installer can only ever install for the current user. Keeps the assisted
installer and the change-directory page. Per-user is also what auto-update
wants: no UAC prompt on every update, and an all-users copy would need
elevation the updater can't obtain silently.

Rejected: `oneClick: true` — simplest guarantee, but drops the
install-directory choice for no extra safety here.

## Cleanup for existing dual installs

Not something the installer can do retroactively: the all-users copy must be
removed via its own uninstaller
(`"C:\Program Files\ED Helper\Uninstall ED Helper.exe" /allusers`). Documented
in the README so anyone who hit this can fix it.
