# ED Helper v1.4 — Fleet Carrier Router

**Date:** 2026-07-24
**Status:** Approved under the standing overnight authorization (recommended-default
choices; user asleep). Probe-verified before design — see the
"Fleet carrier routes" section of `docs/superpowers/notes/2026-07-24-spansh-api-findings.md`
and fixtures `fleetcarrier-route-submit.json` / `fleetcarrier-route-result.json`.
**Builds on:** v1.3 (Exploration Router, merged)

## Purpose

Plot fleet carrier routes (500 ly jumps, tritium budgeting) with the companion-app
advantages: ship-journal prefill, CarrierJump-driven waypoint auto-advance, and
clipboard auto-copy of the next system.

## Probe findings that shape the design

- `POST /api/fleetcarrier/route` takes **id64s, not names** (`source`, repeated
  `destinations`). The app resolves names → id64 via the existing (previously
  unwired) `searchSystems` endpoint inside `plotFleetCarrier`.
- Required params: `source`, `destinations` (repeated), `capacity`, `mass`,
  `capacity_used`, `calculate_starting_fuel`. Carrier stats are hardcoded pairs
  on the site: Fleet = capacity 25000 / mass 25000, Squadron = 60000 / 15000.
- Result: `result.jumps[]` (source is `jumps[0]`, distance 0), 15 fields per jump
  including `fuel_used`, `fuel_in_tank`, `restock_amount`, `must_restock` (int
  0/1), `has_icy_ring` / `is_system_pristine` (booleans), `distance`,
  `distance_to_destination`. **No aggregate totals** — summed client-side.
- Silent-ignore trap re-confirmed live (`used_capacity` accepted → wrong answer).
  Param names in this spec are the verified ones.

## Decisions (autonomous, recommended defaults)

| Topic | Decision |
|---|---|
| Mode | `calculate_starting_fuel: '1'` only ("how much tritium do I need to load") — the site default. Mode 0 (plan with current fuel / market tritium / refuel destinations) is a deferred follow-up. |
| Destinations | Single destination in v1.4 (free text + Colonia / Sagittarius A* quick-picks, same as neutron). Multi-waypoint destination list is a deferred follow-up. |
| Carrier type | Two chips: Fleet (25000/25000) and Squadron (60000/15000) setting `capacity`/`mass`. Cargo used (`capacity_used`) editable number, default 0. |
| Name resolution | `plotFleetCarrier` resolves from/to names via `/systems/search` (exact-name match, case-insensitive; error "Unknown system: <name>" if no match). id64s treated as opaque values passed straight back to Spansh. |
| Tracking | New engine journal event `CarrierJump` (system name), parsed like FSDJump. A third `WaypointTracker` instance advances on **CarrierJump** events (not FSDJump) and auto-copies the next system. |
| Exclusivity | Carrier routes join the travel-route mutual exclusion group: starting carrier clears neutron + exploration and vice versa (single clipboard resource; also keeps the cockpit unambiguous). Trade coexists with any one travel route. |
| Values shown | Per jump: distance, distance-to-go, tritium used, restock badge (`must_restock`), icy-ring/pristine badges. Totals line: jumps (len-1), total distance, total tritium (`sum fuel_used` = the `restock_amount` at `jumps[0]` in mode 1). |

## Architecture (same seams as v1.2/v1.3)

1. **Engine**: add `{ type: 'CarrierJump'; system: string }` to `JournalEvent`
   (types.ts) + parse case (`raw.StarSystem`). State reducer: CarrierJump also
   updates current system **only when the player is aboard** — journal
   CarrierJump events carry `Docked:true` when aboard; keep the reducer change
   minimal: treat like FSDJump for `system` (the event only appears in the
   player's journal when they witness the jump). Existing tests untouched.
2. **SpanshClient.plotFleetCarrier(req)** — resolve names, submit, poll (same
   guard: `state === 'completed'` or non-empty `result.jumps`), map:
   ```ts
   interface PlotFleetCarrierRequest {
     from: string; to: string;
     capacity: number; mass: number; capacityUsed: number;
   }
   interface FleetCarrierWaypoint {
     system: string; jumps: number;            // 0 for source, 1 per jump (tracker contract)
     distance: number; distanceToGo: number;
     fuelUsed: number; restockAmount: number;
     mustRestock: boolean; hasIcyRing: boolean; pristine: boolean;
   }
   interface FleetCarrierRoute {
     waypoints: FleetCarrierWaypoint[];
     totalJumps: number; totalDistanceLy: number; totalTritium: number;
   }
   ```
3. **Host RPC**: `plotFleetCarrier(req)`. **Main**: third
   `WaypointTracker<FleetCarrierWaypoint, FleetCarrierRoute>` fed from the
   watcher fan-out but matching `CarrierJump` events; mutual exclusion wired
   three-ways (carrier/neutron/exploration each clear the other two on start).
   IPC `carrier:plot/start/clear/get/anchor` + `carrier:updated` push.
4. **Renderer**: fourth tool pill "FLEET CARRIER"; FleetCarrierRouter view —
   carrier-type chips, from (ship-prefilled) / to (+ quick-picks), cargo-used
   field; results list with per-jump tritium + badges; totals line; START/CLEAR/
   Copy anchors; exclusivity notice. Cockpit: carrier card (waypoint N of M,
   copied system).

## Validation results — v1.4 (2026-07-24)

- **Render + prefill**: FLEET CARRIER pill (fourth tool) renders; Fleet/Squadron
  chips, From prefilled from the live journal ("Col 285 Sector FG-D a42-1"),
  Cargo aboard field (0), Colonia / Sagittarius A* quick-picks.
- **Live plot with name→id64 resolution**: Col 285 Sector FG-D a42-1 → Colonia
  (Fleet, 0 t cargo) resolved both names via /systems/search and returned a
  45-jump / ~21,873 ly route in seconds.
- **Per-jump display**: source row carries "RESTOCK 3132 t" (restock amount
  visible per review fix); ICY RING and PRISTINE badges render on the correct
  rows; per-jump tritium (75 t / 74 t …) and distance-to-go columns correct.
- **Auto-copy on start**: START ROUTE put the first target waypoint
  ("Col 359 Sector SD-I c10-14") on the Windows clipboard — verified with
  `Get-Clipboard`. Cockpit card showed "FLEET CARRIER · Waypoint 2 of 45 ·
  on clipboard — paste in galaxy map".
- **Three-way exclusion (live)**: with the carrier route active, plotting and
  starting a neutron route (Col 285 → Lave) copied "Lave" to the clipboard and
  cleared the carrier route — FLEET CARRIER tab returned to its form view.
- **CarrierJump auto-advance** couldn't be exercised without an in-game carrier
  jump; covered by the WaypointTracker eventType unit tests (CarrierJump tracker
  ignores FSDJump and vice versa).
- **Clear + shutdown**: neutron Clear route restored the form; app closed
  cleanly (dev process exit 0). 129 tests green (engine 46, app 83).
