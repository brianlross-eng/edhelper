# ED Helper v1.10 — Packaging: installer + portable exe

**Date:** 2026-07-26
**Status:** Approved (Brian: "I need a distributable version of the app. an
install or executable." — building BOTH artifact types removes the choice).
**Builds on:** v1.9 (merged). First phase using the GitHub PR flow.

## Purpose

Turn the dev-only app (`npm run dev`) into distributable Windows artifacts:
a per-user NSIS installer (`ED-Helper-Setup-<version>.exe`) and a portable
single-exe, published as a GitHub Release on brianlross-eng/edhelper.

## Decisions (recommended defaults)

| Topic | Decision |
|---|---|
| Tooling | electron-builder (standard companion to electron-vite). Targets: `nsis` (per-user, one-click off, desktop shortcut) + `portable`. x64 only. |
| Engine host under packaging | THE sharp edge: main spawns the engine-host with `EDHELPER_NODE ?? 'node'` — packaged machines have no Node. Fix: when `app.isPackaged`, spawn `process.execPath` with `ELECTRON_RUN_AS_NODE=1` (Electron binary as Node). Dev behavior unchanged. Verify asar compatibility; `asarUnpack` the host bundle if needed. |
| Native deps | The app's runtime (main + host) must not drag engine-package native deps (better-sqlite3/zeromq) into the bundle — verify what electron-vite bundles from `@edhelper/engine` (watcher/parser are pure fs). If the barrel drags natives in, split imports or externalize. Probe during planning. |
| Identity | productName "ED Helper", appId `com.gumswampsoftware.edhelper`, version from package.json (set 1.0.0). Icon: simple generated orange .ico (placeholder-quality acceptable; better art deferred). |
| Release | Local build (no CI yet — deferred), artifacts attached to GitHub Release `v1.0.0` via `gh release create`. Auto-update deferred (private-repo updates need a token story). |
| Validation | Install the NSIS build on this PC, launch WITHOUT the dev toolchain, verify: journal detected, SHIP tab derives the model, one live Spansh plot, EDDN counters, clean uninstall keeps %APPDATA% settings. Portable exe: launch + one plot. |

## Out of scope

CI builds, code signing (unsigned; SmartScreen warning expected — note in
README), auto-update, macOS/Linux targets, custom artwork.
