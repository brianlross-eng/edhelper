# ED Helper v1.1 — Spansh API Conversion + EDDN Broadcast

**Date:** 2026-07-24
**Status:** Approved design
**Project root:** `D:\EDHelper`
**Builds on:** v1 (engine + cockpit app, both merged to master; see `2026-07-23-edhelper-v1-design.md`)

## Purpose

Convert the app's database queries from the local SQLite mirror to Spansh's free
public API, and turn the EDDN integration around: instead of receiving the
network's data (no longer needed without a local DB), the app broadcasts the
player's own market and discovery data to EDDN — making them a contributor to
the ecosystem Spansh, Inara, and EDSM are built on. Ship/commander info remains
journal-based and never leaves the machine except via the explicit EDDN opt-out
toggle described below.

## Decisions (settled during brainstorming)

| Topic | Decision |
|---|---|
| Local DB in the app | Removed — API-only. (Engine package and CLI keep all local-DB abilities; the 4.2 GB dump and 1.4 GB DB in `D:\EDHelper\data` become deletable at the user's discretion.) |
| Broadcast scope | Market (commodity/3) + discovery (journal/1). Outfitting/shipyard schemas deferred. |
| Broadcast default | ON (this is the user's only EDDN uploader), with a settings kill-switch and a footer broadcast counter. |
| Architecture | **Approach B**: the engine-host child process is retained as the app's network/data process; its internals swap from SQLite+zeromq to Spansh HTTPS + EDDN HTTPS. Process isolation, crash-restart, and the RPC seam stay. |

## Architecture

The engine-host keeps its role and lifecycle (spawned by Electron main,
stdio JSON-RPC, EngineClient auto-restart, fatal suppression) but changes
contents:

### Engine host (child process) — after conversion

1. **SpanshClient** (new, in-host module)
   - Trade planning via Spansh's async job API: `POST https://spansh.co.uk/api/trade/route`
     with the planner parameters, then poll `GET https://spansh.co.uk/api/results/<job>`
     until complete; map results into the existing `TradeRoute`/`Hop` shapes so the
     renderer is unchanged.
   - Station/system resolution and autocomplete via
     `https://spansh.co.uk/api/systems/search` and `https://spansh.co.uk/api/stations/search`.
   - The implementation plan's first task verifies exact request/response field
     names empirically against the live API (the endpoints above are the ones the
     Spansh website itself calls; shapes are confirmed before any dependent code
     is written).
   - Sets a distinct User-Agent (`EDHelper/<version>`); respects HTTP 429 with
     exponential backoff; one in-flight route job at a time.
2. **EddnUploader** (new, in-host module)
   - Receives journal events forwarded from Electron main over RPC.
   - On `Docked` + the journal `Market` event: reads `Market.json` from the
     journal directory (path forwarded by main) and emits an EDDN
     `commodity/3` message.
   - On jump/dock/scan-type events: emits `journal/1` messages with the
     schema-required augmentation (StarPos etc. where required) and stripping of
     localised/personal fields.
   - `POST https://eddn.edcd.io:4430/upload/` (gzip body). Header carries
     `uploaderID` (commander name — the EDDN gateway anonymizes/hashes it before
     relaying), `softwareName: "EDHelper"`, `softwareVersion`.
   - Outbound queue: retry ×3 with backoff per message, then drop and count;
     never blocks or delays any user-facing feature.
   - Honors the broadcast toggle (RPC-settable, default ON).
3. **Removed from the host**: `openDatabase`, the EDDN receive loop
   (`EddnClient`/zeromq), and all SQL. `better-sqlite3`/`zeromq` leave the app's
   dependency list (the engine package keeps them for the CLI).

### RPC contract changes

- `plotTrade(req)` — same request/response shape as v1, now backed by Spansh.
- `resolveStation` — replaced by `searchStations(query)`/`searchSystems(query)`
  for autocomplete-style lookup (plotTrade takes names directly; Spansh resolves).
- `getDataHealth()` — returns Spansh reachability (status + last-success
  timestamp + last error) and EDDN broadcast counters (sent, dropped, queued)
  instead of dump age and receive counters.
- New: `journalEvent(ev, context)` — fire-and-forget forwarding of each journal
  event from main's watcher (context carries the journal directory for
  Market.json reads).
- New: `setEddnUpload(enabled)` — the kill-switch.
- Events pushed by host: `eddn` (broadcast counters) and `spansh` (reachability
  transitions), replacing the old receive-side `eddn` event.

### Electron main

- Journal watcher unchanged (ship state, route tracking) plus one addition:
  every parsed event is forwarded to the host via `journalEvent`.
- Settings: a persisted `eddnUpload` boolean (simple JSON settings file in
  Electron `userData`), applied to the host at startup and on toggle.

### Renderer

- Trade Planner UI unchanged except: station field gains validation feedback
  from `searchStations` when a plot fails with "unknown station".
- Footer: "Spansh ✓/✗ (last checked …)" replaces the dump-age badge;
  "Broadcasting · N sent" (or "Broadcast off") replaces the receive counter;
  the journal indicator stays. Clicking the broadcast entry toggles the
  kill-switch.

## Privacy

- Ship, commander, credits, and route state: read from local journal files,
  displayed locally, never transmitted.
- With broadcasting ON, market snapshots and discovery-class journal events are
  sent to EDDN under the standard anonymization (gateway hashes uploaderID;
  localised/personal fields stripped per schema). The kill-switch stops all
  uploads immediately.
- Spansh API queries carry only the query parameters (station names, filters) —
  no commander identity.

## Error handling

- Spansh unreachable/timeout: planner surfaces "Spansh unreachable — try again
  shortly", footer indicator red; journal features unaffected.
- HTTP 429: backoff and retry transparently; surface "Spansh is rate-limiting"
  only if a request ultimately fails.
- EDDN gateway 4xx (schema rejection): count as dropped, log the gateway's
  message to the host's stderr for diagnosis; never retry schema rejections.
- EDDN gateway 5xx/network: retry ×3 with backoff, then drop and count.
- Host crash: existing EngineClient restart behavior; queued-but-unsent EDDN
  messages from the dead host are lost (accepted — market data is re-sent on
  next dock).

## Testing

- **SpanshClient**: mocked-HTTP unit tests for request shaping, job polling,
  result mapping into `TradeRoute`, 429/backoff, and error paths. One recorded
  live fixture captured during the API-verification task keeps the mapping
  honest.
- **EddnUploader**: golden tests — journal fixture events + a `Market.json`
  fixture in, exact payloads out, validated against the published EDDN JSON
  schemas (vendored copies of commodity/3 and journal/1). Queue/retry/drop
  logic tested with a fake transport.
- **RPC/host**: existing child-process test harness updated to the new methods.
- **Live smoke test** (final task): plot a real route through the app via
  Spansh; verify one real commodity message accepted by EDDN's **beta/test
  gateway** before switching the endpoint to production; confirm footer
  indicators and kill-switch behavior.

## Out of scope for v1.1

- Local-DB mode in the app (CLI retains it; app code paths removed).
- Outfitting/shipyard EDDN schemas.
- Other Spansh tools (Neutron Plotter etc.) — v1.1 converts the plumbing; new
  tools come after, each much cheaper to add once the API client exists.
- Packaging/installer (unchanged from v1 deferral), route persistence.
