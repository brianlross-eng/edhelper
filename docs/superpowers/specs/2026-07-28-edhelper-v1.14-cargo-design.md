# ED Helper v1.14 — Cargo inventory awareness

**Date:** 2026-07-28
**Status:** Approved (Brian: cockpit shows 50/50t but not WHAT; Trade Planner
ignores loaded cargo).

## Journal facts (probe in-task against the real journal dir)

The `Cargo` journal event (Vessel "Ship") carries `Inventory:
[{Name, Name_Localised?, Count, Stolen}]` on the initial event; later events
may omit it — the authoritative current inventory lives in `Cargo.json` in the
journal dir (same pattern as Market.json). Verify both shapes against the real
files; fixture wins.

## Decisions

| Topic | Decision |
|---|---|
| Engine | `Cargo` event parse gains `inventory?: Array<{ name; count }>` (prefer Name_Localised, else Name lowercased; skip zero counts). ShipState gains `cargoInventory?: Array<{ name; count }>` — reducer: set from event when inventory present; when a Cargo event has count but NO inventory, keep the previous inventory only if its total equals the new count, else clear (stale-guard). Existing tests unmodified. |
| Watcher | On a `Cargo` event WITHOUT inventory, `JournalWatcher` (Electron main, has fs + dir) reads `Cargo.json` (try/catch, skip on error) and synthesizes the inventory into the state it emits. Simplest seam: watcher post-processes state after reduce; document it. |
| Cockpit | Under the cargo bar: comma list "silver 32 · gold 18" (muted, wraps), `data-testid="cargo-inventory"`. Empty hold → nothing. |
| Trade Planner | Cargo (t) prefills with FREE space (`cargoCapacity - cargoUsed`, min 0) instead of full capacity — but ONLY when cargoUsed > 0. When cargoUsed > 0 show a muted note under the field row: "Hold: <inventory list or 'Nt loaded'> — planning with free space (<free>t). Edit Cargo (t) to override." (`data-testid="cargo-note"`). Field stays fully editable; prefill-guard semantics unchanged (only fills when empty). |
| Release | v1.0.4 (auto-updates to installed apps). |
