# ED Helper v1.17 — Copy button for trade destinations

**Date:** 2026-07-28
**Status:** Approved (Brian, after weighing in-game plotting: "how about just a
copy button, so I don't have to do the highlight and Ctrl-C part, just inject
the destination into the clipboard?").

## Context: why NOT in-game plotting

Frontier exposes no API to control the game; the clipboard is the ceiling for
every third-party tool. The only unofficial path is simulated input (scan-code
keystrokes, as VoiceAttack does), which requires the app to run on the SAME
machine as the game, depends on galaxy-map UI state and keybindings, and is a
ToS gray area. Brian declined it in favour of the clipboard shortcut. Recorded
here so the option isn't re-litigated from scratch later.

## Gap being fixed

Every TRAVEL route (neutron/exploration/carrier/tourist/galaxy/colonisation)
auto-copies the next waypoint on jump and has per-waypoint Copy buttons (v1.2+).
The TRADE route has neither — grep confirmed zero Copy affordances in
RouteChecklist/TradePlanner/CockpitPanel — so trading meant highlighting the
system name and Ctrl-C by hand.

## Decisions

| Topic | Decision |
|---|---|
| Manual, not automatic | Trade routes deliberately do NOT auto-copy: trade coexists with one active travel route (by design since v1.3), and that route owns the clipboard on every jump. A user-pressed button can never fight it. |
| What is copied | The destination SYSTEM name only (`hop.toSystem`) — what the galaxy map search box wants; the station name would break the search. |
| Where | **Cockpit card only** (`cockpit-copy`, "Copy destination" for the current hop). Per-hop buttons in the checklist were shipped in 1.0.7 and removed in 1.0.8 at Brian's request — "redundant and doesn't fit": the checklist advances automatically, so the current hop is the only one you ever need, and the left card stays visible on other tool tabs. |
| Plumbing | `clipboard:write` IPC → `clipboard.writeText` in main (same seam the travel trackers use), `copyText` on the preload API, optional `onCopy` prop on the components so tests stay independent of Electron. |

## Testing

Component tests: checklist button copies the destination system; cockpit button
copies the current hop's destination; components render and no-op without an
onCopy handler. Live smoke: click Copy, verify the clipboard via Get-Clipboard.

## Validation results — v1.17 (2026-08-02)

- Installed 1.0.7 on this PC and plotted a real 4-hop route from the live
  journal position (Ross 720 / Raleigh Orbital, 66 t, 6.3M cr). Clipboard was
  pre-seeded with a sentinel string.
- "Copy destination" on the LEFT cockpit card → clipboard became `VESPER-M4`
  (destination SYSTEM only, sentinel replaced), verified with Get-Clipboard.
  A per-hop checklist Copy button copied the same destination for its hop.
- 196 tests green (engine 56, app 193). Clean shutdown.

## Amendment — cockpit-only (2026-08-02, v1.0.8)

Brian, on seeing 1.0.7: "remove the copy button on the right please. It's
redundant and doesn't fit." Per-hop Copy buttons removed from the trade
checklist (and the now-unused `onCopy` plumbing dropped from RouteChecklist /
TradePlanner); the cockpit card button is the single copy affordance. A test
pins the checklist as copy-button-free so they don't creep back.
