# ED Helper v1.18 — "No repeat stations" trade option

**Date:** 2026-08-02
**Status:** Approved (Brian: "I need an option to prevent loops. I got stuck in
an area that was pretty much A-B-A-B, but I ran the route faster than they
could restock.")

## Finding

No new API work needed: Spansh's trade endpoint already takes a `unique` flag
(listed in the v1.1 DECLARED SHAPE all along) and ED Helper has been hardcoding
`unique: '0'` since v1.1. Exposing it is a one-line client change.

Live A/B from Brian's own start point (Ross 720 / Raleigh Orbital, 66 t,
6.3M cr, 4 hops) — the unique=0 run reproduces his complaint exactly:

- `unique=0`: Raleigh Orbital ⇄ Alien's Abduction, four hops, two stations.
- `unique=1`: Raleigh Orbital → Remek Colony (Tara) → Jeanne D'arc's Dream →
  Alvarado Beacon → Kendrick Hub — four distinct stations.

## Decisions

| Topic | Decision |
|---|---|
| Surface | Third checkbox beside Surface stations / Fleet carriers: **"No repeat stations"**, `data-testid="unique-stations"`, with a tooltip explaining the restock rationale. |
| Default | OFF — matches Spansh's own default and keeps existing behaviour for people who WANT a tight shuttle (it is the highest cr/hr when stock allows). |
| Plumbing | `PlotTradeRequest.uniqueStations?: boolean` → `unique: '1'\|'0'`. The v1.13 M-pad recovery re-plot passes the same request object through, so a recovered route keeps the setting. |

## Testing

Client test asserts the flag maps both ways in the submitted form; component
test asserts default-off and that ticking it reaches the request. Live A/B
above is the behavioural proof.
