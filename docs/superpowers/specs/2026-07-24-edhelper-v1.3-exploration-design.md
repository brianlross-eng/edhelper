# ED Helper v1.3 — Exploration Router (Road to Riches + Ammonia + Earth-like + Rocky/Metal)

**Date:** 2026-07-24
**Status:** Approved under the standing overnight authorization (recommended-default
choices; user asleep). Probe-verified before design: all four Spansh tools share
`POST /api/riches/route`, differing only by `body_types` — see the
"Exploration routes" section of `docs/superpowers/notes/2026-07-24-spansh-api-findings.md`
and fixtures `riches-route-*.json` / `ammonia-route-result.json`.
**Builds on:** v1.2 (Neutron Plotter, merged)

## Purpose

One "EXPLORATION" tool covering four of the originally requested Spansh tools via a
route-type selector: Road to Riches (high-value bodies), Ammonia Worlds,
Earth-likes, Rocky/Metal. Waypoint tracking with clipboard auto-copy works exactly
like the neutron plotter — plus each waypoint lists the bodies to scan and their
scan/mapping values.

## Decisions (autonomous, recommended defaults)

| Topic | Decision |
|---|---|
| One tool, four modes | Selector maps to `body_types`: Road to Riches → omitted; Ammonia → `["Ammonia world"]`; Earth-likes → `["Earth-like world"]`; Rocky/Metal → `["Rocky body","High metal content world"]`. min_value: 100,000 for R2R (editable), 1 for the variants (hidden). |
| Tracker reuse | The neutron tracker's logic generalizes to `WaypointTracker` (generic over waypoint payloads with a `system` field); NeutronTracker and the new ExplorationTracker are two instances of it. Existing neutron tests must stay green through the refactor. |
| Clipboard exclusivity | Neutron and exploration routes are MUTUALLY EXCLUSIVE (both are travel routes that auto-copy on FSDJump — two at once would fight over the clipboard). Starting one clears the other, and the UI says so. The trade route coexists with either. |
| Defaults | radius 25 ly, max_results 50, max_distance 50,000 ls, loop off, avoid_thargoids off, use_mapping_value off (follow-up probe needed before exposing). |
| Values shown | Per body: subtype, distance-to-arrival (ls), scan value, mapping value, terraformable flag. Route totals summed client-side (API provides none). Always use `id64` strings, never the precision-lossy `id`. |

## Architecture (same seams as v1.2)

1. **SpanshClient.plotExploration(req)** — same job/poll machinery against
   `/riches/route`; form-encoded with `traditional` repeated `body_types` keys.
   ```ts
   interface PlotExplorationRequest {
     from: string; to?: string; jumpRange: number; radius: number;
     maxResults: number; maxDistance: number; minValue: number;
     bodyTypes: string[]; // [] = Road to Riches
     loop: boolean; avoidThargoids: boolean;
   }
   interface ExplorationBody {
     name: string; subtype: string; distanceToArrival: number;
     scanValue: number; mappingValue: number; terraformable: boolean;
   }
   interface ExplorationWaypoint { system: string; jumps: number; bodies: ExplorationBody[]; }
   interface ExplorationRoute {
     waypoints: ExplorationWaypoint[]; totalJumps: number;
     totalScanValue: number; totalMappingValue: number; totalBodies: number;
   }
   ```
2. **WaypointTracker generalization** (`src/main/waypoint-tracker.ts`): the current
   NeutronTracker logic parameterized as `WaypointTracker<W extends { system: string }>`
   with route shape `{ waypoints: W[] }`; `neutron-tracker.ts` re-exports a
   NeutronTracker built on it (public API unchanged — all 8 existing tests must
   pass unmodified). ExplorationTracker is a second instance. Generic active
   state: `ActiveWaypointRoute<W> { waypoints, currentWaypoint, waypointStatus[], copiedSystem }`
   (ActiveNeutronRoute stays as the neutron alias for IPC compatibility).
3. **Host RPC**: `plotExploration(req)`. **Main**: ExplorationTracker instance
   (same injected clipboard), fed from the same watcher event fan-out; mutual
   exclusion enforced in main — `exploration:start` calls `neutron.clear()` first
   and vice versa. IPC channels `exploration:plot/start/clear/get/anchor` +
   `exploration:updated` push.
4. **Renderer**: third tool pill "EXPLORATION"; ExplorationRouter view — route-type
   selector (4 chips), from/to/range/radius/max-results/min-value fields
   (from + range ship-prefilled), loop + avoid-thargoids checkboxes; results as
   waypoints with expandable body lists (subtype badge, ls, scan/map cr values);
   START/CLEAR/Copy anchors identical to neutron; totals line (bodies, jumps,
   scan cr, mapping cr). Cockpit: exploration card (waypoint N of M, copied
   system, remaining-value tally is out of scope v1.3).

## Validation results — v1.3 (2026-07-24)

- **Render + prefill**: EXPLORATION tab shows the four mode chips (Road to Riches /
  Ammonia Worlds / Earth-likes / Rocky/Metal); From and jump range prefilled from
  the live journal (commander's system "Col 285 Sector FG-D a42-1", 12.607 ly);
  defaults radius 25 / max results 50 / min value 100,000 rendered; Loop and
  Avoid Thargoids checkboxes present.
- **Plot from real ship state**: R2R plot from the commander's actual system
  returned 1 system / 0 bodies — correct behavior, real data sparsity in that
  region (the probe saw the same near Lave), not a bug.
- **Long-range plot**: Sol → Colonia R2R returned 52 systems · 341 bodies ·
  scan 64,933,798 cr · map 235,925,762 cr; per-body rows rendered subtype,
  distance (ls), and scan/map values; client-side totals line correct.
- **Auto-copy on start**: START ROUTE put the first target waypoint
  ("Scutum Dark Region IM-W d1-49") on the Windows clipboard — verified with
  `Get-Clipboard`.
- **Mutual exclusion (live)**: with the exploration route active, plotting and
  starting a neutron route (Col 285 → Lave) copied "Lave" to the clipboard and
  cleared the exploration route — EXPLORATION tab returned to its form view with
  no active checklist. The "Starting replaces any active neutron route." notice
  renders on the exploration form (and the mirror notice on the neutron form).
- **Jump auto-advance** couldn't be exercised without flying; covered by the
  WaypointTracker unit tests (neutron suite unchanged + exploration instance tests).
- **Clear + shutdown**: Clear route restored the neutron form (values preserved);
  app closed cleanly (dev process exit 0, no orphans). 114 tests green
  (engine 44, app 70).
