# ED Helper v1.10 — Packaging: installer + portable exe Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the dev-only app into two distributable Windows x64 artifacts — a per-user NSIS installer (`ED-Helper-Setup-1.0.0.exe`) and a portable single exe (`ED-Helper-Portable-1.0.0.exe`) — built locally with electron-builder and published as GitHub Release `v1.0.0` on brianlross-eng/edhelper. Everything ships unsigned (SmartScreen caveat documented in a new README).

**Architecture:** electron-vite already bundles main, preload, renderer, AND the engine-host into `packages/app/out/` with zero runtime node_modules needed — so the package is `out/**` + `package.json` inside an asar, nothing else. Two code changes make that true and packageable: (1) a tree-shake setting that drops two leftover bare `require("better-sqlite3")`/`require("zeromq")` side-effect requires from the main bundle (verified during planning — see probe facts), and (2) a packaged-mode engine-host spawn: `app.isPackaged` → re-exec `process.execPath` (the installed Electron binary) with `ELECTRON_RUN_AS_NODE=1`, since packaged machines have no Node. The spawn decision is a new pure function `engineSpawnSpec()` (unit-tested; `index.ts` stays thin glue). The icon is a dependency-free Node script that writes a 256×256 PNG-in-ICO (no ImageMagick on this machine).

**Tech Stack:** TypeScript strict ESM, Electron 37, electron-vite 3, electron-builder 26, vitest, NSIS (fetched by electron-builder).

## Probe facts (build reality checked 2026-07-26 while writing this plan)

- **The host bundle exists where main expects it.** `npm run build -w @edhelper/app` emits `packages/app/out/main/index.js` (28.8 kB), `packages/app/out/main/engine-host.js` (42.1 kB), `packages/app/out/main/chunks/rpc-BtTSEIGI.js`, `out/preload/index.js`, `out/renderer/{index.html,assets/*}`. `index.ts` spawns `join(__dirname, 'engine-host.js')` — same directory as the main bundle, so the relative layout survives packaging unchanged.
- **NATIVE LEAK CONFIRMED in the main bundle — and the fix is verified.** `out/main/index.js` lines 4 and 9 contain bare `require("better-sqlite3")` and `require("zeromq")`. Cause: `main/index.ts` imports `JournalWatcher`/`DEFAULT_JOURNAL_DIR` from the `@edhelper/engine` barrel; the barrel also re-exports `openDatabase` (→ better-sqlite3) and `EddnClient` (→ zeromq). Rollup tree-shakes the unused *named exports* but keeps empty side-effect requires because **external modules default to "has side effects"**. In a packaged app with no node_modules those requires throw at startup → main process dead. Fix **tested during planning and then reverted** (plan-only branch): adding `treeshake: { moduleSideEffects: 'no-external' }` to the main `rollupOptions` → rebuild → **zero** matches for `better-sqlite3|zeromq|bindings` in `out/main/index.js`. The **engine-host bundle was already clean** (only `node:fs`, `node:path`, `node:zlib`, and the rpc chunk — it imports engine *types* only).
- **Env passthrough is already correct.** `EngineClient.start()` spawns with `env: { ...process.env, ...this.spawnSpec.env }` and `EngineClientSpawnSpec` already has an optional `env` field (`packages/app/src/main/engine-client.ts` lines 6-10, 37-40). So passing `env: { ELECTRON_RUN_AS_NODE: '1' }` in the packaged spec adds the flag while `EDHELPER_JOURNAL_DIR` / `SPANSH_API_URL` keep flowing through to the host for tests. No EngineClient change needed.
- **Asar strategy: keep asar ON, do NOT unpack the host.** Reasoning: Electron initializes its asar fs-patching in `ELECTRON_RUN_AS_NODE` mode — that is precisely how `child_process.fork()` works from inside `app.asar` (the Electron docs bless fork with asar-internal script paths; spawning `process.execPath` with `ELECTRON_RUN_AS_NODE=1` is what fork does under the hood, minus the IPC channel we don't use — our RPC is over stdio pipes, which `EngineClient` already sets up). So `args: [<path inside app.asar>/out/main/engine-host.js]` loads fine. Fallback documented in Task 2 (failure mode 2) in case reality disagrees.
- **Toolchain:** electron **37.10.3**, electron-vite **3.1.0** (vite 5.4.21 does the SSR build), node 24.16.0, npm 11.13.0, gh **2.92.0** present and authed (remote = `https://github.com/brianlross-eng/edhelper.git`). **electron-builder is NOT installed** anywhere in the tree → add `electron-builder@^26.0.12` (the 26.x line is the one that supports Electron 37). **No ImageMagick** (`magick` not found) → icon is generated by a small dependency-free Node script (raw PNG chunks + zlib, wrapped in an ICO container).
- **Monorepo wrinkle & chosen approach:** `@edhelper/app` has `dependencies: { "@edhelper/engine": "*", better-sqlite3, zeromq, react, react-dom }`, all hoisted to the root node_modules. None are needed at runtime (renderer bundles react; engine source is bundled into main; natives are dead after the tree-shake fix). So electron-builder must NOT collect production deps: `files` whitelist `out/**` + `package.json` + `"!node_modules/**"`, with `npmRebuild: false` / `nodeGypRebuild: false` so it never tries to rebuild better-sqlite3/zeromq against Electron's ABI. Fallback if dep collection still trips on the workspace dep is documented in Task 2 (failure mode 1).
- **Housekeeping facts:** no `README.md` exists at repo root (Task 4 creates it). `.gitignore` has `out/` and `dist/` but not `release/` (Task 1 adds it). App `package.json` version is `0.1.0`; `engine-host.ts` hardcodes `SOFTWARE = { softwareName: 'EDHelper', softwareVersion: '0.1.0' }` for EDDN headers — the two uploader/builder tests construct their own opts objects, so bumping the constant to `1.0.0` breaks nothing (verified by grep: tests reference their own literals, not the constant).
- **userData location changes between dev and installed.** electron-builder writes `productName: "ED Helper"` into the packaged app's package.json, so the installed app's `app.getPath('userData')` = `%APPDATA%\ED Helper` (dev resolves from the raw package name). The smoke checklist looks for `%APPDATA%\ED Helper\settings.json`. electron-builder's NSIS `deleteAppDataOnUninstall` defaults to `false` → uninstall keeps settings, as the spec requires.

- [ ] **Step 3: Implement.** Create `packages/app/src/main/engine-spawn.ts`:

```ts
import { join } from 'node:path';
import type { EngineClientSpawnSpec } from './engine-client.js';

export interface EngineSpawnInputs {
  /** Electron's app.isPackaged. */
  isPackaged: boolean;
  /** process.execPath — the installed Electron binary when packaged. */
  execPath: string;
  /** __dirname of the main bundle (engine-host.js sits beside index.js in out/main). */
  mainDir: string;
  /** process.env.EDHELPER_NODE — dev-only override for the Node binary. */
  edhelperNode?: string;
}

/**
 * Dev machines run the engine host under plain `node`; packaged machines have
 * no Node at all, so the packaged app re-execs its own Electron binary with
 * ELECTRON_RUN_AS_NODE=1. Electron keeps its asar fs-patching active in that
 * mode (this is how child_process.fork works from inside app.asar), so the
 * host path may live inside app.asar. EngineClient merges spec.env OVER
 * process.env, so EDHELPER_JOURNAL_DIR / SPANSH_API_URL still pass through.
 */
export function engineSpawnSpec(inputs: EngineSpawnInputs): EngineClientSpawnSpec {
  const hostPath = join(inputs.mainDir, 'engine-host.js');
  if (inputs.isPackaged) {
    return { command: inputs.execPath, args: [hostPath], env: { ELECTRON_RUN_AS_NODE: '1' } };
  }
  return { command: inputs.edhelperNode ?? 'node', args: [hostPath] };
}
```

- [ ] **Step 5: Icon.** Create `packages/app/scripts/make-icon.mjs` (dependency-free; writes a single-entry ICO whose payload is a 256×256 PNG — valid on Windows Vista+ and exactly what electron-builder wants):

```js
// Generates build/icon.ico (256x256, PNG-in-ICO) with zero dependencies —
// no ImageMagick on this machine. Elite-orange rounded square with a dark
// right-pointing chevron. Placeholder-quality per the v1.10 spec; real
// artwork is a deferred follow-up.
import { deflateSync } from 'node:zlib';
import { mkdirSync, writeFileSync } from 'node:fs';
import { dirname, join } from 'node:path';
import { fileURLToPath } from 'node:url';

const SIZE = 256;
const R = 40; // corner radius
const ORANGE = [0xff, 0x71, 0x00, 0xff]; // Elite orange
const DARK = [0x12, 0x10, 0x0d, 0xff]; // app window background (#12100d)

function insideRoundedSquare(x, y) {
  const cx = Math.min(Math.max(x, R), SIZE - 1 - R);
  const cy = Math.min(Math.max(y, R), SIZE - 1 - R);
  return (x - cx) ** 2 + (y - cy) ** 2 <= R * R;
}

// Right-pointing chevron: two 28px-thick strokes meeting at x=148+28, y=128.
function insideChevron(x, y) {
  if (y < 56 || y > 200) return false;
  const edge = y <= 128 ? 76 + (y - 56) : 76 + (200 - y);
  return x >= edge && x <= edge + 28;
}

// Raw RGBA scanlines, each prefixed with PNG filter byte 0.
const STRIDE = 1 + SIZE * 4;
const raw = Buffer.alloc(SIZE * STRIDE);
for (let y = 0; y < SIZE; y++) {
  for (let x = 0; x < SIZE; x++) {
    const o = y * STRIDE + 1 + x * 4;
    const px = insideRoundedSquare(x, y) ? (insideChevron(x, y) ? DARK : ORANGE) : [0, 0, 0, 0];
    raw[o] = px[0];
    raw[o + 1] = px[1];
    raw[o + 2] = px[2];
    raw[o + 3] = px[3];
  }
}

const CRC_TABLE = new Int32Array(256).map((_, n) => {
  let c = n;
  for (let k = 0; k < 8; k++) c = c & 1 ? 0xedb88320 ^ (c >>> 1) : c >>> 1;
  return c;
});
function crc32(buf) {
  let c = 0xffffffff;
  for (const b of buf) c = CRC_TABLE[(c ^ b) & 0xff] ^ (c >>> 8);
  return (c ^ 0xffffffff) >>> 0;
}
function chunk(type, data) {
  const len = Buffer.alloc(4);
  len.writeUInt32BE(data.length);
  const body = Buffer.concat([Buffer.from(type, 'latin1'), data]);
  const crc = Buffer.alloc(4);
  crc.writeUInt32BE(crc32(body));
  return Buffer.concat([len, body, crc]);
}

const ihdr = Buffer.alloc(13);
ihdr.writeUInt32BE(SIZE, 0); // width
ihdr.writeUInt32BE(SIZE, 4); // height
ihdr[8] = 8; // bit depth
ihdr[9] = 6; // color type: RGBA
const png = Buffer.concat([
  Buffer.from([0x89, 0x50, 0x4e, 0x47, 0x0d, 0x0a, 0x1a, 0x0a]),
  chunk('IHDR', ihdr),
  chunk('IDAT', deflateSync(raw, { level: 9 })),
  chunk('IEND', Buffer.alloc(0)),
]);

// ICO container: ICONDIR (6 bytes) + one ICONDIRENTRY (16 bytes) + PNG.
const ico = Buffer.alloc(22);
ico.writeUInt16LE(1, 2); // type: icon
ico.writeUInt16LE(1, 4); // image count
ico[6] = 0; // width 256 -> 0
ico[7] = 0; // height 256 -> 0
ico.writeUInt16LE(1, 10); // color planes
ico.writeUInt16LE(32, 12); // bits per pixel
ico.writeUInt32LE(png.length, 14); // bytes in resource
ico.writeUInt32LE(22, 18); // image data offset

const out = join(dirname(fileURLToPath(import.meta.url)), '..', 'build', 'icon.ico');
mkdirSync(dirname(out), { recursive: true });
writeFileSync(out, Buffer.concat([ico, png]));
console.log(`wrote ${out} (${22 + png.length} bytes)`);
```

  needed), optional install directory, desktop shortcut.
- **ED-Helper-Portable-\<version\>.exe** — single portable exe, no install.

Windows x64 only. The app reads the game journal from
`%USERPROFILE%\Saved Games\Frontier Developments\Elite Dangerous` automatically.
Settings live in `%APPDATA%\ED Helper\settings.json` and survive uninstall.

### SmartScreen warning

Releases are **not code-signed** (yet), so the first launch shows
"Windows protected your PC". Click **More info → Run anyway**.
